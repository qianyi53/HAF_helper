# 业务逻辑说明

按架构分层（L1 采集 → L2 筛选 → L3 解析 → L4 发布）说明每层的业务规则、判定逻辑与数据契约。数据流与追溯链见文末 §6。

---

## 1. L1 采集层（`scripts/nnsa_crawler.py`）

**数据源**：国家核安全局官网"核安全文件"栏目。列表为静态分页（`index.html`、`index_1.html`…，约 200 页 / 3000 篇，按日期倒序），详情页分新旧两套模板，字段结构一致。

**业务规则**

| 规则 | 逻辑 |
|---|---|
| 采集范围 | `cutoff_date`（起始日期）之后的全部文函；cutoff 存于 JSON 的 `meta`，首次运行用 `--since` 指定 |
| 增量窗口 | `boundary = max(cutoff, 上次运行日)`：逐页扫描，某页最大日期 < boundary 即停止（后续只会更老） |
| 全窗校验 | `--full-scan` 从 cutoff 起逐页核对，可发现"站内撤稿" |
| 名称 | meta `ArticleTitle`（列表标题属性为空，需取详情页） |
| 分类 / 发布机关 | 本栏目恒定：`国家核安全局文件` / `国家核安全局`（页面无独立字段） |
| 生成日期 | meta `PubDate`（发布日期） |
| 成文日期 | 正文落款：取正文中**最后一次**出现的"XXXX年X月X日" |
| 文号 | 仅认**标题中**或**独立成行**的文号（如"环核〔2026〕12号"）。正文句内的〔20xx〕xx号基本是引用他文文号，**不采信** |
| 正文 | `content_body_box` 容器按 div 深度配对提取（兼容嵌套），剥离 `<style>/<script>` 后转纯文本 |
| 附件 | 正文内相对/绝对链接中命中 `W0*` 或 pdf/doc/docx/wps/xls/xlsx/ceb 者，转绝对地址 |
| 唯一键 | `doc_id` = 详情页 URL 中的 `tYYYYMMDD_数字` |
| 撤稿 | 窗口内文函在官网列表中消失 → 打 `site_status=missing_in_list`（**不删除**）；`--remove-missing` 才真删 |
| 失败重试 | 抓取失败的文函记入 `meta.errors`，下轮**优先**重试 |
| 请求礼貌 | 默认 1.5s/次；失败退避重试 3 次 |

## 2. L2 筛选层（`haf/rules.py` + `haf/classifier.py`）

### 2.1 域门控（决定"是否纳入"）

命中 `核安全设备` / `注册登记` / `单位资质` 任一关键词 → 域内；否则整篇排除。

**排除类别**（已裁定 Q-L2-1~3，均可由 `rules.py` 调整）：核电厂运行/建造许可证、放射性废物处理/贮存/处置许可证、放射性物品运输容器许可、质量保证大纲、在役检查/调试/装换料/维修大纲、场址选择审查意见书、核安全导则等。

> 实测：567 篇 → 域内 229 篇，反向核查零误检。

### 2.2 文档级事件（只判标题）

| 优先级 | 事件 | 规则 |
|---|---|---|
| 1 | 不予延续 | 标题含"不予(延续\|批准\|注册登记\|许可)" |
| 2 | 吊销 | 标题含"吊销" |
| 3 | 注销 | 标题含"注销" |
| 4 | 变更 | 标题含"变更"（注意公文用词是"变更**许可**活动范围"，不一定带"证"字） |
| 5 | 延续 | 标题含"延续" |
| 6 | 颁发 | 标题含"颁发"（"批准延续/批准变更"中的"批准"是公文措辞，**不算**颁发事件） |

**为什么只用标题**：正文匹配会被内嵌语句污染——实测 8 篇颁发通知正文含"同时注销"、12 篇正文含"变更"，若用正文判文档级事件会误标。

### 2.3 证件类型（标题优先、正文兜底；先判注册登记）

- `境外注册登记确认书`：命中"注册登记确认书/境外单位注册登记"
- `许可证`：命中"核安全设备…许可/许可…核安全设备"

### 2.4 活动种类（只判标题）

设计 / 制造 / 安装 / 无损检验，可多选；标题未注明则留空（明细在附件，由 L3 补）。

### 2.5 内嵌事件（句级，正文）

| 内嵌事件 | 规则 | 业务含义 |
|---|---|---|
| 注销 | `同时注销…(许可证\|确认书)`，句界内 200 字 | 换证时同时注销原证（境外单位长英文名常见） |
| 变更 | `注册登记范围变更` | 境外注册登记范围变更（与首次注册合并发文） |
| 变更 | `(单位\|公司)名称变更` | 持证单位更名（换发新证） |

### 2.6 标签体系与使用注意（裁定 Q-L2-5）

标签族：`事件:` / `证件类型:` / `活动种类:`，`类别:值` 格式可扩展；**单文函可带多个事件标签**。

| 注意 | 说明 |
|---|---|
| 否定案例 | "不予延续"文函通常同时带 `事件:延续` 标签 → 统计延续业务量时**先排除** `事件:不予延续` |
| 变更三语义 | 许可活动范围变更（87）/ 注册登记范围变更（12）/ 单位名称变更（2）共用 `事件:变更`，可结合 `match_reasons` 区分 |
| 输出契约 | 原始字段全透传 + `labels` + `match_reasons`（逐条命中依据）+ `need_pdf_parse`；**域外文函也写入**（`labels=[]`），保证全量可追溯、边界调整无需重爬 |

## 3. L3 解析层（`haf/pdf_fetch.py` / `pdf_parser.py` / `llm.py` / `chain.py` / `state.py`）

### 3.1 附件获取

- 仅处理域内且 `need_pdf_parse=true` 的文函附件；按 `data/pdf/<doc_id>/` 存放，索引 `_index.json` 记录 URL、本地路径、字节数、`sha1`、状态。
- **文件头校验**：后缀为 `.pdf` 但文件头不是 `%PDF-` 的，直接标记 `非PDF` 跳过（实测 1 个），避免每轮重试。
- 同一附件 URL 可能被多篇文函引用（实测 1 个 URL 被 11 篇引用）→ 以「文函 × 附件」为单位处理。

### 3.2 分块（一证一块 / 一页一家一条）

扫描每页**前 4 行**（跳过"附件 1"这类前缀行）判定锚点：

| 块类型 | 锚点 | 切法 |
|---|---|---|
| `license` 许可证块（优先） | 页首出现 `民用核安全设备(设计\|制造\|安装)许可证` | 起点 = 该页；终点 = 下一块起点前；块内 = 证书页 + 条件页 + 附表页 + 能力参数续页（实测 3~5 页） |
| `overseas` 境外确认书块 | 页首出现 `一、…`（序号+国别+单位名）或 `…注册登记确认书` | 一单位一块（1~2 页） |
| `scope_only` 范围表块 | 页首出现 `单位名 + 民用核(电)安全设备…许可活动范围表/许可证` | 多单位变更时**一页一家**；同一单位的连续页去重（跨页续表不新开块） |

每个块携带 `page_start/page_end`，最终写入记录的"附件页码"，用于原文定位。

### 3.3 许可证块：字段与事件

| 字段 | 规则 |
|---|---|
| 证字号 | `国核安证字[SZA]?（yy）nn号`（S=设计、Z=制造、A=安装；去空白归一） |
| 单位名称 / 法定代表人 / 单位住所 | 键值行提取，键名允许字符间空格（"单 位 名 称："），值可跨行直到下一个键 |
| 设备类别 / 核安全级别汇总 | 顿号切分为数组；过滤含"国家核安全局/审查/条件"等标记词的长句，避免整句污染 |
| 活动种类 | 由证件类型推导：设计/制造/安装 → 对应活动；境外注册登记 → 设计+制造 |
| 有效期 | 优先"有效期至 YYYY年M月D日"；否则"许可证有效期 N 年" + 发证日期推算（+N 年 -1 天），并在原文中标注"（自…推算）" |
| 事件 | 条件页含"延续申请" → 延续；含"取证/首次/颁发" → 颁发 |

> 有效期在**条件页**（第 2 页起）而非证书首页，属关键业务位置约定。

### 3.4 范围表解析（设备粒度核心）

| 环节 | 规则 |
|---|---|
| 表头识别 | 白名单列名映射（`HEADER_MAP`）：设备种类 / 设备类别 / 设备品种（`设备品种/设备名称`、`设备名称` 归一到设备品种）/ 民用核设施类别 / 核安全级别 / 主要关键工艺 / `…活动范围及…完成形式` / 活动场所 / 备注 |
| 表头合并 | 表头可能被 PDF 拆成多行碎片（实测最多 8 行）→ 先合并连续短行再识别；**数据行不会被误判为表头**（要求单元格短且整格等于表头名） |
| 参数组 | `设计能力特征参数` / `制造能力特征参数` 是"大类套小类"：其下子列（公称通径 DN、设计压力 MPa、设计温度 ℃ / 结构形式、载荷等级 kN、典型设备名称）按**表头跨度**归属该组，统一切到 JSON |
| 独立参数列 | 铸锻件/储罐/换热器类常见独立列也在 `PARAM_META` 登记：材料类别、成品重量(t)、堆型功率、壁厚(mm)、管板厚度(mm) |
| 合并单元格 | 9 个"语义可继承"列（设备种类/类别/品种/民用核设施类别/核安全级别/活动范围及完成形式/活动场所/主要关键工艺/备注）**向下填充**（PDF 合并单元格在后续行为空，语义为"同上"） |
| 数值解析 | `≤1050` → `{值:1050, 上限:true, 单位:DN}`；`≤5030（事故工况下≤8675）` → 附加 `附加.事故工况`；`≤500` 保留上限标记；`/`、`-` 视为无值；纯文字（如"液压"）→ `{原文:…}` |
| 多值/列表 | `、`/`,`/`;` 切分为数组（典型设备名称、材料类别、主要关键工艺） |
| 分包项目 | 从备注中抽取"分包项目：…"，支持编号列表与"80吨以上吊装设备租赁"这类**保留前导数字**的值 |
| 空格 | 中文单元格去换行空格；拉丁为主（英文单位名/地址）保留单词间单空格 |
| 记录产出 | 无单位名且无范围行的纯名单/说明类附件**不产出记录**（避免脏数据） |

### 3.5 境外注册登记块

- 单位名：取"单位名称"字段；缺失时从页首"一、美国 Emerson…"里取序号后的单位名。
- 范围：`表一 设计活动注册登记范围` / `表二 制造活动注册登记范围` → 两张表按顺序打 `活动类别`（设计 / 制造）。
- 字段：单位所在国、法定代表人、单位住所、设备类别、核安全级别、设备品种（`设备品种/设备名称`）。

### 3.6 LLM 兜底策略（`haf/llm.py` + `prompts.py`）

| 环节 | 规则 |
|---|---|
| 触发条件 | ① 许可证块缺证字号/单位名/范围行；② 范围表块或境外块无范围行；③ **范围行关键列（设备类别/核安全级别）缺失比例 > 30%** |
| 不触发 | 规则结果完整时不调用 LLM（实测全量仅 86 块需兜底，约占 11%） |
| 载荷 | 块头（文档/附件/页范围/块内证字号）+ 页文本 + 表格 markdown；单块 > 12000 字符自动按页分片多次调用 |
| 结果合并 | LLM 行经规范化（补键、按备注补分包项目、默认源页）；规则残缺时**以 LLM 行为准**整体替换，否则仅补空缺 |
| 缓存 | 键 = 模型 + 提示词 + 输入哈希 → `data/llm_cache/`；重跑零消耗；用量累计写 `_usage.json` |
| 失败隔离 | 单块异常记录后继续（不影响其他块/其他附件）；输出支持围栏、夹带文字、**截断 JSON 修复** |
| 模式 | 默认 `deepseek-flash` 且关闭思考链；`--no-llm`（纯规则）/ `--llm-only`（对照）可切换 |

### 3.7 版本链（"同一份许可证"的业务定义）

- **许可证身份**：`(规范化单位名, 证件类型)` —— 规范化只做空白/括号字符剔除（"甲公司 （本部）" ≡ "甲公司(本部)"），避免同一实体因标点差异被拆成两份许可证。
- **证字号是版本属性**：延续/换证会换号（实测 S（21）20号 → S（26）17号），故不作为主键，只作版本字段与业务检索键。
- 版本排序：`(生效日期, version_id)`；`变更` 版本自动**继承上一版证字号**（变更通知附件只有"变更后"范围表，不含证字号）。
- 版本来源事件：颁发 / 延续 / 变更（不含否定的"不予延续"，其作为独立版本参与状态判定）。
- 活动种类与设备类别/核安全级别汇总：对同一许可证的所有版本汇总（去重排序），反映"历史上曾有的范围"。

### 3.8 变更内容（diff）业务逻辑

变更附件是**"变更后全量表"**，官网不提供差异标注，故变更内容由相邻版本对比推导：

| 项 | 规则 |
|---|---|
| 行键 | `(设备类别, 设备品种, 核安全级别, 活动场所)` |
| 三类操作 | 新增（新键）/ 删除（旧键消失）/ 修改（同键下对比 能力特征参数、活动范围及完成形式、活动场所、备注、分包项目、工艺） |
| 摘要 | 规则生成，如"制造许可证：新增 11 项设备范围；修改 1 项（涉及 备注、活动范围及完成形式）"；完全一致则记为"与上一版一致" |
| 关联 | `change_id = C{变更通知doc_id}-{license_id}`（一份通知可同时变更同一单位的设计+制造两证，需各自成条）；`diff基础版本` 记录对比的上一版 |
| 基线 | 受"不回溯 2007–2020"（Q-L1-1）限制，首个可见版本之后的变更才可推出完整"变更前" |

### 3.9 状态判定（业务优先级）

```
1) 最近版本事件 = 不予延续        → 无效（依据：不予延续）
2) 命中"同时注销"引用且晚于该版本 → 已注销（依据：换证/收回时注销 + 来源文函 + 日期）
3) 有效期止存在且已过 今日         → 无效（依据：有效期已过 YYYY-MM-DD）
4) 其他                            → 有效（依据：最近事件 + 日期）
5) 来源文函在官网列表中消失        → 打「数据标志=来源文函官网已撤下」；
                                     若原判为有效则降级为「待核实」（保留原依据说明）
```

注销引用抽取：从 L2 标注 `事件:注销` 的文档正文中，取 `同时注销…(许可证|确认书)` 片段，切掉"持有的/民用核安全设备…"等修饰后得到**被注销单位名**（剥离国别前缀），与许可证的规范化单位名比对匹配。

## 4. L4 发布层（`haf/db_builder.py` + `haf/pipeline.py`）

### 4.1 表结构与关系

```
documents (doc_id PK)
   ├─ licenses (license_id PK; 来源doc_id/当前版本id)
   │     ├─ license_versions (version_id PK; license_id → licenses; change_id → changes)
   │     │      ├─ scope_items (scope_item_id PK)          ← 设备粒度核心
   │     │      └─ registry_scopes (registry_scope_id PK)  ← 境外注册登记范围
   │     └─ changes (change_id PK)
```

- 外键：建库时批量写入临时关闭外键（`licenses.当前版本id ↔ license_versions.version_id` 互为引用，顺序无法同时满足），写入后开启并执行 `PRAGMA foreign_key_check` 校验（当前 0 问题）。
- 无独立单位表（裁定 Q-L3-4）：单位"最新名称"冗余在各表。

### 4.2 视图（可读主数据）

| 视图 | 业务口径 |
|---|---|
| `view_license_current` | 一行一证：单位、证字号、证件类型、活动种类、状态+依据、有效期、设备类别/核安全级别汇总、版本数、变更次数、最近变更日期+摘要、范围行数、数据标志、官网链接、附件链接、附件页码 |
| `view_device_index` | 一行 = 设备类别×品种×许可证：**只取当前版本**（`v.version_id = l.当前版本id`）的范围行，含能力特征参数（可读串 + JSON）、关键工艺、持证单位、证字号、状态、来源事件/生效日期、来源文函状态、官网链接、附件页码 |

能力参数可读串规则：`DN≤1050 / P≤8.9MPa / T≤320℃`（名称+比较符+值+单位，单位与名称相同则不重复）；列表类参数 `材料:不锈钢、碳钢`。

### 4.3 增量与重建

- **L4 每次全量重建**（秒级）：保证"视图/汇总/状态"与最新解析结果强一致，不做增量 upsert。
- 增量发生在 L1（新增文函）与 L3（按附件指纹跳过未变附件）；L2 每次全量重跑（秒级、幂等）。
- 重建输入：`data/parsed_records.json`（模型）+ `data/labeled_docs.json`（文函主表，含正文与撤稿状态）。

### 4.4 交付形态

SQLite 单文件 `data/db/haf.db`（6 表 + 2 视图 + 外键 + 索引），可选 `--csv` 导出分表（`documents` 表由 L2 产物生成，保证与 SQLite 一致）。

## 5. 跨层机制

| 机制 | 说明 |
|---|---|
| `doc_id` 贯穿 | L1 生成 → L2 打标 → L3 每条记录与版本携带 `doc_id`/官网链接/附件链接/页码 → L4 可回链原文与附件页 |
| 增量状态 | `data/parse_state.json`：键 = `文函\|附件`，值含 `sha1`、解析模式、记录数。指纹未变且模式一致才跳过；`records=0` 表示该附件本就无有效记录（不需重解析） |
| 模式敏感 | 关闭 LLM 跑出的结果不会用于启用 LLM 的轮次（反之亦然），避免复用低质量结果 |
| 失败隔离 | 附件级（记 `meta.errors`，下轮重试）、块级（记 `block_error`）、LLM 片级（记 `llm_usage.errors`）三层，单点失败不中断流程 |
| 幂等可复跑 | 各层输出可整体重生成；L2/L4 全量重建，L1/L3 增量，任何阶段可单独运行 |

## 6. 数据流与追溯链

```
官网文函 ──L1──▶ nnsa_policy_docs.json (doc_id)
   └─L2──▶ labeled_docs.json (labels / match_reasons / need_pdf_parse)
              └─L3──▶ 附件 PDF ──分块──▶ 记录 ──版本链/diff/状态──▶ parsed_records.json
                        （每条记录带 证字号 / 页码 / 附件链接 / doc_id）
                                        └─L4──▶ haf.db（licenses / versions / scope_items / changes）
```

**追溯链**：任一设备参数（`scope_items`）→ 其版本（`license_versions.version_id`）→ 来源文函（`doc_id`）→ 官网链接 + 附件 URL + **附件页码**；变更内容同理指向变更通知的 doc_id 与页码。
