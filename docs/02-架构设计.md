# 架构设计

原则：**轻量、中文可读、层间以文件为契约**——每层读上一层产物、写自己的产物，任何一层可独立重跑与人工核验。
各层业务判定细节见《05-业务逻辑说明》，此处只讲结构与约定。

## 1. 分层

```
L1 采集  scripts/nnsa_crawler.py        → data/nnsa_policy_docs.json
L2 筛选  haf/rules.py + classifier.py   → data/labeled_docs.json
L3 解析  haf/pdf_fetch.py / pdf_parser.py / llm.py / chain.py / state.py
                                        → data/parsed_records.json
L4 发布  haf/db_builder.py + pipeline.py→ data/db/haf.db（交付物）
编排     haf/pipeline.py（weekly = L1→L4 一键）
L5 前端  frontend/index.html（浏览器版，查云数据库）
         frontend/build_wechat.py + wechat_template.html → frontend/wechat/*.html（微信版，数据内嵌）
         frontend/haf-sync/sync.mjs（haf.db → 云数据库增量同步，供浏览器版读取）
```

L5 说明：浏览器版（单页 HTML，经 SDK 只读查询 WorkBuddy 云数据库）与微信版（数据内嵌单页 HTML，零外部依赖）**同源同口径**——都以 `data/db/haf.db` 为唯一数据源，展示"当前版本（链尾）"快照；云数据库由 `haf-sync` 按主键增量同步，页面本身无写功能。

## 2. 目录结构

```
HAF_info/                项目根（工作区即项目目录）
├── docs/                文档（01 需求 / 02 架构 / 03 计划 / 04 使用说明 / 05 业务逻辑 / 06 数据字典 / 问答对齐 / reports/）
├── scripts/             nnsa_crawler.py（L1）、M3 分析脚本、夹具生成、L4 验收与质量速查
├── haf/                 核心包（L2~L4）
├── tests/               单元测试 + fixtures/（真实公文裁剪样本）
├── data/                各层产物；db/ 为交付物；pdf/ 与 parsed_records.json 不入 git
├── frontend/            L5 前端：index.html（浏览器版）、build_wechat.py + wechat_template.html + wechat/（微信版）、
│                        wrapper/（包装页留档）、haf-sync/（云数据库同步，含独立 README 与 .gitignore）
├── archive/             历史验证产物（verify_demo.py 等）与旧仓库备份（HAF-agent-git-backup/，不入库）
├── config.example.json  LLM 配置模板（可入库）；config.local.json 为本地密钥（不入库）
└── .workbuddy/          开发记忆（勿删）
```

取舍：不搞 `src/` 布局、无 ORM/框架；`haf/` 平铺包 + `scripts/` 工具脚本；前端独立成 `frontend/`（自带构建脚本与同步工具），与后端流水线只通过 `data/db/haf.db` 一个文件耦合。

## 3. 数据契约

| 层间 | 产物 | 关键字段 |
|---|---|---|
| L1→L2 | `nnsa_policy_docs.json` | `doc_id`(唯一键)、名称、分类、发布机关、生成日期、成文日期、文号、正文、附件及链接、链接、`site_status`(撤稿标记) |
| L2→L3 | `labeled_docs.json` | L1 全字段透传 + `labels`（`类别:值`，可多标签）+ `match_reasons`（命中依据）+ `need_pdf_parse`；**域外文函亦保留**（`labels=[]`） |
| L3→L4 | `parsed_records.json` | `records`（块级解析记录）+ 组装模型：`licenses` / `license_versions` / `scope_items` / `changes` / `registry_scopes` |
| L3 状态 | `parse_state.json` | 键 `文函\|附件` → `sha1`、解析模式、记录数（增量判定） |
| L4 | `haf.db` | 6 表 + 2 视图（结构见《05-业务逻辑说明》§4） |
| L4→L5 | `haf.db`（唯一数据源） | haf-sync 按主键 diff 同步上云（浏览器版读取）；build_wechat.py 直接读库内嵌（微信版） |

## 4. 交付形态（裁定 Q-L4-1）

**SQLite 单文件** `data/db/haf.db`：6 表 + 2 视图 + 物理外键 + 索引；可 `--csv` 附加导出分表。
> 依据：workbuddy database 可直接导入 SQLite（需求方实测确认）；资料库对 CSV 的支持仅覆盖单表，多表外键/视图无官方依据。

## 5. 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 采集/下载 | `urllib` + `re`（标准库） | 站点纯静态、无反爬 |
| 筛选 | 纯规则，规则外置 `haf/rules.py` | 实测域门控零误检、事件零未分类 |
| PDF 解析 | `pdfplumber` | 表格/合并单元格/跨页表支持好，10/10 样本可用 |
| LLM | 直连 API（默认 `deepseek-flash`，关闭思考链）；占位符配置 + 块级缓存 | 仅作兜底（实测约 11% 块），成本可忽略 |
| 存储 | JSON（层间）+ SQLite（交付） | 可核验 + 平台无关 |
| 前端（L5） | 单页 HTML/原生 JS；浏览器版读云数据库（CDN SDK），微信版数据内嵌零依赖 | 轻量、免运维；两种发布入口同源同口径 |
| 云同步（L5） | `node:sqlite` + workbuddy-cloud-sdk（Node ≥22.5） | 按主键三方 diff，幂等；写通道走密钥校验的云函数 |
| 环境 | Python 3.14 + venv + git | — |

## 6. 关键机制

1. **doc_id 贯穿**：官网文档 ID 是全程关联主键，解析记录回指原文与附件页码。
2. **增量与幂等**：L1 按 `cutoff + last_run` 增量；L3 按 `文函|附件` 内容指纹跳过未变附件；L2/L4 全量重建（秒级）。
3. **失败隔离**：附件级、块级、LLM 片级三层隔离，记录后继续，下轮重试。
4. **规则外置**：筛选规则与提示词分别集中在 `haf/rules.py`、`haf/prompts.py`，需求方可直接调整。
5. **撤稿同步**：L1 标 `site_status`；L4 打「数据标志」并把有效状态降级为「待核实」，不静默删除。
