## L3 解析层

### Q-L3-1 LLM 接入与成本 ✅🏁
- **裁定**：留 API 占位符（需求方填 key）；给出全量 token 评估。
- **落地**：占位符配置（env → `config.local.json`，模板 `config.example.json`）+ 块级缓存；实测全量输入 1.12M / 输出 1.16M token，实际兜底模式仅 86 块（≈11%）。
- **后续调整**：早期的"本地 key 文件"方式已废弃（用户要求），统一为 `config.local.json`。

### Q-L3-2 输出数据结构 ✅🏁
- **裁定**：认可多表结构；两点要求——①调研 workbuddy database 是否支持多表外键；②主数据可读性要强，需加可读视图表。
- **调研**：资料库确认支持 CSV，但**多表外键/视图无官方依据**；workbuddy 可直连主流关系库且元数据含主外键。后经需求方确认 **database 可直接导入 SQLite**（见 Q-L4-1）。
- **落地**：**6 表 + 2 真视图 + 物理外键**（无单位表，见 Q-L3-4）。

### Q-L3-3 解析技术路线 ✅🏁
- **裁定**：认可「页级预分块 + 确定性解析优先 + 轻量 LLM 兜底」。

### Q-L3-4 单位表 ✅🏁
- **裁定**：**不需要独立单位表**，保留最新名称即可。
- **落地**：单位名冗余在各表；版本链以（规范化单位名, 证件类型）为主键。

### Q-L3-5 解析质量阈值与补全策略 🔵（悬置）
- **问题**：设备类别覆盖 99.6%、核安全级别 90%、能力特征参数 61%（部分类型本无此列）；是否追加一轮 LLM 补全（<0.2M token）？
- **裁定**：**先悬置**，后续再定。

  4. 是否需要多单位横向参数对比与导出（Excel/PDF）？

- **落地**（2026-09-27 前端开发，实际形态为方案 A/B 之外的第三路——云数据库只读 + 单页 HTML）：

  - 无效/已注销：**不隐藏**，以状态徽标区分（有效/无效/已注销/待核实）。
  - 对比导出、境外单列入口：本期未做；境外单位由搜索自然覆盖（含所在国副标题）。
