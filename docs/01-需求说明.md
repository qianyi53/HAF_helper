# 需求说明

## 1. 目标

采集国家核安全局（NNSA）官网公开文函，筛选出**核安全设备相关许可类**文函，解析 PDF 附件为**设备粒度**的结构化数据，产出 **SQLite 数据库文件**，并基于该库提供**单页 HTML 前端查询页面**。

## 2. 工作流

| 阶段 | 内容 | 状态 |
|---|---|---|
| ① 采集 | 官网"核安全文件"栏目全量 + 增量采集 | ✅ |
| ② 筛选打标 | 筛出目标文函并打标签 | ✅ |
| ③ 解析入库 | 下载解析 PDF，结构化入库 | ✅ |
| ④ 数据库生成 | 产出 workbuddy 可导入文件（SQLite） | ✅ |
| ⑤ 增量维护 | 周期增量更新全流程 | ✅ |
| ⑥ 前端查询 | 单页 HTML（浏览器版查云数据库 + 微信版数据内嵌） | ✅ |

## 3. 筛选范围（已裁定）

**纳入**：
1. 民用核安全设备**许可证**——设计/制造/安装/无损检验活动的颁发、延续、不予延续、变更；
2. 境外单位**注册登记确认书**——首次注册、延续、范围变更；
3. **许可证吊销/注销、单位资质吊销**（2021 年以来无独立通知，均为内嵌于颁发/延续通知的"同时注销"信息）。

**排除**：未明确包含的一律排除——核电厂运行/建造许可证、放射性废物许可、放射性物品运输容器许可、质量保证大纲、核安全导则等。

**数据范围**：2021-01-01 起（不回溯历史）。567 篇文函中域内 229 篇。

## 4. 解析需求

- **设备粒度**：可查某设备类别/品种下的相关许可证及其**最新能力特征参数**；附件中"许可活动范围表"信息完整纳入。
- **许可证状态**：可查有效 / 无效（含不予延续、到期未延续、已注销），并有判定依据。
- **变更记录**：含变更内容、时间与双方官网链接；变更内容由相邻版本 diff 推导（附件只提供"变更后"全量表）。
- **可追溯**：每条记录携带**官网链接 + 附件 URL + 附件页码**。
- **字段策略**：必然出现的字段作固定列；偶发/大类套小类的（如制造能力特征参数）以 JSON 存储。
- **准确度**：设备参数解析不要求 100% 准确，但需"基本准确"。

## 5. 交付

- **形态**：SQLite 单文件（`data/db/haf.db`），6 表 + 2 视图 + 物理外键（裁定 Q-L4-1）。
- **可读性**：除规范表外提供可读视图（`view_license_current`、`view_device_index`）。
- **前端（L5，已落地）**：两类查询——① 按设备类别/品种查最新许可证与参数；② 按单位查最新许可证与参数。展示口径为**当前版本（链尾）快照**（裁定 Q-L4-2 及 L5 落地记录见《问答对齐》）：
  - 浏览器版：`frontend/index.html`，经 SDK 只读查询云数据库（随周更自动更新）；
  - 微信版：`frontend/wechat/核安全设备许可证查询.html`，数据内嵌单页（~1.5MB、零外部依赖），由 `frontend/build_wechat.py` 从 haf.db 构建。

## 6. 非功能需求

- **轻量**：优先标准库；解析仅依赖 `pdfplumber`；不引入框架/ORM。
- **可读**：中文命名、中文注释、字段名贴合官网口径；分层业务规则集中于《业务逻辑说明》。
- **可复跑**：各阶段幂等、可独立重跑；每层中间产物落盘 JSON。
- **增量**：周更只处理新增/变更，附件按内容指纹跳过。
- **礼貌抓取**：1.5s/请求。
