## 一、融合方案与最终结构

**原则**：后端流水线（L1~L4）与前端（L5）只通过 `data/db/haf.db` 一个文件耦合；前端独立成 `frontend/` 目录，自带构建脚本与云同步工具。

```
HAF_info/                项目根（工作区即项目目录）
├── docs/                01~06 + 问答对齐 + 用户留言 + reports/（原 HAF-agent）
├── haf/                 L2~L4 核心包（原 HAF-agent）
├── scripts/             L1 爬虫、分析/验收脚本（原 HAF-agent）
├── tests/               98 项单测 + fixtures（原 HAF-agent）
├── data/                各层产物；db/haf.db 为交付物（原 HAF-agent）
├── frontend/            ★ 新增 L5 前端（原 HAF前端）
│   ├── index.html                 浏览器版单页（查云数据库）
│   ├── wechat_template.html       微信版模板
│   ├── build_wechat.py            微信版构建脚本（原 tools/）
│   ├── inspect_db.py              库结构巡检（原 tools/）
│   ├── wechat/核安全设备许可证查询.html   微信版产物（~1.56MB，数据内嵌）
│   ├── wrapper/核安全设备许可证查询.html  iframe 包装页（已实测废弃，留档）
│   └── haf-sync/                  haf.db → 云数据库增量同步（Node ≥22.5，含独立 README/.gitignore）
├── archive/             历史验证产物 + HAF-agent-git-backup/（旧仓库历史备份，不入库）
├── README.md / requirements.txt / config.example.json / config.local.json（密钥，不入库）
└── .workbuddy/memory/   两项目开发记忆合并（勿删）
```
