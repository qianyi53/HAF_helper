# SQLite 交付物 数据字典

交付物：`data/db/haf.db`（SQLite 单文件，6 表 + 2 视图 + 物理外键 + 索引，约 5.6MB）
本文件说明**每个表、视图、字段的含义**，并对所有 **JSON / 多值字段**给出：**存储形态、语义类别（标签型 / 数据型）、解析方法、取值清单、注意事项**。

## 0. 通用约定

| 项 | 约定 |
|---|---|
| 编码 | UTF-8 |
| 日期 | 文本，`YYYY-MM-DD`（ISO）；时间戳为 `YYYY-MM-DDTHH:MM:SS` |
| 中文列名 | SQL 中建议加双引号：`SELECT "设备类别汇总" FROM licenses` |
| 空值 | 无值用 `NULL`；JSON 字段无内容时存 `'[]'`（数组）或 `'{}'`（对象），**不是 NULL** |
| 主键类型 | 文本（有业务含义的稳定 ID），非自增整数 |
| 只读使用 | 交付库用于查询；重建由 `python -X utf8 -m haf.pipeline --stage l4` 全量生成 |
| JSON 函数 | 库自带 SQLite 3.50.4，**JSON1 可用**（`json_extract` / `json_each` / `json_array_length` 均已实测） |

### JSON / 多值字段的两种语义类别（贯穿全文）

| 类别 | 含义 | 前端用法 |
|---|---|---|
| **标签型** | 受控或有限取值集合（枚举、固定词表），取值本身即"标签" | 可直接做筛选（下拉/多选/彩色标签）与聚合统计 |
| **数据型（非标注）** | 结构或取值不固定：自由文本、任意键名、嵌套结构 | **不可当标签筛选**，需按结构渲染（键值表、原文段落、diff 视图） |

## 1. 对象总览

```
documents(doc_id)
  ├── licenses(license_id)            ← 一证一条，含状态（链尾快照）
  │     ├── license_versions(version_id)   ← 每次颁发/延续/变更一版
  │     │     ├── scope_items(scope_item_id)      ← 设备粒度明细（核心）
  │     │     └── registry_scopes(registry_scope_id) ← 境外注册登记范围
  │     └── changes(change_id)        ← 变更记录（含 diff 明细）
视图（只读派生，查询用）
  ├── view_license_current  一行一证（可读主表，20 列）
  └── view_device_index     一行 = 设备类别×品种×许可证（仅当前版本，16 列）
```

**外键映射（物理外键已启用，`PRAGMA foreign_key_check` 通过）**

## 8. JSON / 多值字段专项说明（重点）

> 判定规则：**标签型** = 取值受控或有限，可直接做筛选项；**数据型** = 自由文本/任意键/嵌套结构，只能按结构渲染。

### 8.1 `documents.事件标签` — 标签型（非 JSON）

- 形态：**文本**，顿号分隔（如 `颁发、注销`）。
- 解析：`row["事件标签"].split("、")`（JS: `.split("、")`）。
- 取值（实测）：`颁发` 95、`变更` 101、`延续` 49、`注销` 8、`不予延续` 3。
- 注意：域外文函该字段为空串；多标签为常态（一篇文函可同时"颁发 + 注销"）。

### 8.2 枚举字段（非 JSON 的标签型）

| 字段 | 取值（实测频次） |
|---|---|
| `licenses.状态` | `有效` 544 / `已注销` 4 / `无效` 4 |
| `licenses.证件类型` | `民用核安全设备制造许可证` 224 / `…境外单位注册登记确认书` 172 / `…设计许可证` 144 / `…安装许可证` 11 / **`其他:` 1（异常，见 §9-Q1）** |
| `licenses.数据标志` | 当前全为 `NULL`；预留 `来源文函官网已撤下` |

### 8.3 `licenses.活动种类` — JSON 数组 · **标签型**

```jsonc
["设计", "制造"]        // 取值仅三种：设计 / 制造 / 安装
```
- 实测：`制造` 393、`设计` 312、`安装` 11（按证件计数）。
- 解析：
```python
acts = json.loads(row["活动种类"] or "[]")            # Python
```
```js
const acts = JSON.parse(row.活动种类 || '[]');        // JS
```
```sql
-- SQL：按标签筛选（JSON1）
SELECT COUNT(DISTINCT l.license_id) FROM licenses l, json_each(l.活动种类)
WHERE json_each.value = '设计';                       -- → 312
```
- 用途：筛选项直接可用；空数组 `[]` 表示未知（见 §9-Q1）。

### 8.4 `licenses.设备类别汇总` — JSON 数组 · **标签型（未归一）**

- 内容：该证**所有版本**出现过的设备类别去重汇总（约 50 个不同取值）。
- Top 值：`阀门` 83、`管道和管配件` 76、`传感器` 74、`热交换器` 58、`仪控系统机柜` 43、`支承件` 43、`铸锻件` 42、`压力容器` 40…
- 用途：作为"该证覆盖哪些设备类别"的**筛选标签**；但注意与 `scope_items.设备类别` 相比，此处为**历史并集**，而设备明细页应使用当前版本的 `scope_items`。

### 8.5 `licenses.核安全级别汇总` — JSON 数组 · **标签型（未归一，含脏值）**

```jsonc
["核安全1", "2", "3级"]      // 由证书页"核安全1、2、3级"按顿号切分的残留
```
- 实测 24 个不同取值：`3级` 226、`1E 级` 143、`核安全1` 123、`2` 121、`核安全2` 101、`1E级` 82、`核安全1级` 45、`核安全3级` 33、`核安全级` 27…（另有 5 个明显脏值，如 `'核安全1级无损检验注册登记范围检查活动范围…'`）
- **结论：当前不可直接当标签使用**。前端应：① 优先用 `scope_items.核安全级别`（行级、更干净）；② 若必须用汇总字段，先做归一词表（`1E 级`→`1E级`、`核安全1`+`2`+`3级`→`核安全1、2、3级`）。

### 8.6 `scope_items.能力特征参数` — JSON 对象 · **数据型（重点）**

**形态**：`{参数名: 参数值}`，共 **66 种参数名**，参数值有 3 种结构：

```jsonc
{
  // ① 数值型（最常见）：带上限标记与单位；"附加"承载括号内条件值
  "公称通径": {"值": 1050, "上限": true, "单位": "DN"},
  "载荷等级": {"值": 5030, "上限": true, "单位": "kN",
               "附加": {"事故工况": {"值": 8675}}},
  // ② 文本型：原文照录（非数值，不能参与大小比较）
  "结构形式": {"原文": "卧式、立式、单级、多级"},
  // ③ 列表型：枚举值数组
  "典型设备名称": ["低压安注泵", "中压安注泵", "辅助给水泵"],
  // ④ 兜底键：列名未识别时，整格文本落在 "值"
  "值": {"原文": "适用环境条件：安全壳内（累积辐照剂量：1450kGy，LOCA）鉴定寿命：40年"}
}
```

**解析（Python，推荐）**：
```python
import json
def fmt_params(raw):
    """→ [(参数名, 展示值, 单位, 备注)]，兼容三种结构"""
    out = []
    for k, v in json.loads(raw or "{}").items():
        if isinstance(v, list):
            out.append((k, "、".join(map(str, v)), "", ""))
        elif isinstance(v, dict) and "值" in v:
            note = "；".join(f"{c}:{d.get('值')}{d.get('单位') or ''}"
                             for c, d in (v.get("附加") or {}).items())
            out.append((k, f"{'≤' if v.get('上限') else ''}{v['值']}", v.get("单位") or "", note))
        elif isinstance(v, dict) and "原文" in v:
            out.append((k, v["原文"], "", ""))
    return out
```

**解析（SQL，JSON1）**：
```sql
SELECT json_each.key                                   AS 参数名,
       json_extract(json_each.value, '$.值')           AS 数值,
       json_extract(json_each.value, '$.单位')         AS 单位,
       json_extract(json_each.value, '$.上限')         AS 上限标记,
       json_extract(json_each.value, '$.原文')         AS 原文
FROM scope_items s, json_each(s.能力特征参数)
WHERE s.设备类别 = '阀门' AND json_each.key = '公称通径';
```

**注意事项**
1. **不可断言固定列**：不同设备类别的参数名不同（阀门=通径/压力/温度；泵=流量/轴功率；铸锻件=材料类别/成品重量；传感器=适用环境条件/鉴定寿命）。
2. `能力特征参数可读` 是**已格式化的摘要**（`DN≤1050 / P≤8.9MPa / T≤320℃`），适合列表页；完整参数用 JSON。
3. 键名存在少量变体（`公称通径` vs `公称通径（DN）`、`公称通径（mm）`；`材料类别` vs `材质类别`），前端若做"按参数筛选"需先做键名映射。
4. 兜底键 `值`（879 次）表示**列名未识别**的自由文本，应归入"其他参数"分组展示，不要当参数名。
5. 空对象 `{}` 表示该行无参数（多为安装类/境外表）。

### 8.9 `changes.变更明细` — JSON 对象 · **数据型（diff 结构）**

```jsonc
{
  "新增": [ {设备种类, 设备类别, 设备品种, 民用核设施类别, 活动类别, 核安全级别,
             能力特征参数, 主要关键工艺, 活动范围及完成形式, 活动场所, 备注, 分包项目, 源页} ],
  "删除": [ /* 与"新增"同结构 */ ],
  "修改": [
    {
      "行键": ["阀门", "仪表阀", "2、3级", "江苏省盐城市…"],   // [设备类别, 设备品种, 核安全级别, 活动场所]
      "字段变更": [
        {"字段": "能力特征参数", "变更前": {…}, "变更后": {…}},
        {"字段": "活动范围及完成形式", "变更前": "…", "变更后": "…"}
      ]
    }
  ]
}
```
- **新增/删除** 元素 = 完整的范围行对象（键名与 `scope_items` 一致，其中 `能力特征参数`/`主要关键工艺`/`分包项目` 仍是需再解析的 JSON 字符串）。
- **修改** 元素 = `行键`（4 元数组，定位到具体范围行）+ `字段变更` 列表（每项含 `字段` / `变更前` / `变更后`；前后值可能是字符串，也可能是对象）。
- 解析示例：
```python
d = json.loads(change["变更明细"] or "{}")
新增数, 删除数, 修改数 = len(d.get("新增", [])), len(d.get("删除", [])), len(d.get("修改", []))
for m in d.get("修改", []):
    行键 = m["行键"]                     # [设备类别, 设备品种, 核安全级别, 活动场所]
    for ch in m["字段变更"]:             # ch["字段"] / ch["变更前"] / ch["变更后"]
        ...
```
```sql
SELECT c.change_id,
       (SELECT COUNT(*) FROM json_each(c.变更明细, '$.新增')) AS 新增,
       (SELECT COUNT(*) FROM json_each(c.变更明细, '$.删除')) AS 删除,
       (SELECT COUNT(*) FROM json_each(c.变更明细, '$.修改')) AS 修改
FROM changes c;
```
- 数值构成（实测，按 JSON 解析统计）：88 条变更中含**新增** 52 条、含**删除** 54 条、含**修改** 53 条（一条变更可同时含多类）；`diff基础版本` 当前无空值。
- 用法建议：默认只展示 `变更摘要`；点击"展开"再渲染 diff（新增绿、删除红、修改黄）。
